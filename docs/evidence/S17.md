## What was built

| Where                                          | What                                                                                                                                                                                                                                                                                                                                                                                                              |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `crates/app/src/stop.rs`, `cli.rs`, `main.rs`  | `kosse stop <target> [--ports <p,…>] [--json] [--here \| --project <dir>] [--instance-port <n>]` and `kosse force` (same arguments). Only `<pid>.<start>` with `--ports` is sent; every other target, and every answer that signalled nothing, is a refusal listing the exact confirming commands. | `crates/app/src/failure.rs`                    | Exit codes for the new codes; in text mode the confirming commands follow the error line, one per line, then `(process, project)`.                                                                                                                                                                                                                                                                                |
| README, CONTRIBUTING, CHANGELOG, agent-surface | Command row, exact syntax, records and exit codes; the S17 outcome, the exit-code table rows for actions, and D1 marked accepted.                                                                                                                                                                                                                                                                                 |

Exit codes: 0 `exited`; 1 `stillRunning`, `respawned`, `endpointTaken` (signalled, ports not free), and `notFound` when a name, port or PID matches no observed process; 3 refused with nothing signalled; 4 `noInstance`, `observationFailed`, `actionFailed`. Ambiguity (a name matching several processes) is a refusal (3) listing one command per candidate, since the agent must choose an identity either way.

## Tests added (each guards a rule)

All run the real `kosse` binary against a real `kosse serve --port 0 --probe-only= --act-only=<fixture PIDs>` with `KOSSE_CONFIG_DIR` pointing at a directory that cannot exist, and owned `kosse-fixture` processes. Expected identities and ports come from the fixtures' records and `lsof`. The one-action-per-second limit is respected by retrying on `rateLimited` (polling, no fixed sleep).

| Test                                                                      | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `stop::a_name_is_refused_with_the_command_that_then_stops_it`             | No stop by name or port alone: a configured service name (with and without `--here`), a port, a PID and an identity without `--ports` each exit 3 with nothing signalled and print exactly `kosse stop <pid>.<start> --ports <every lsof port> --instance-port <n>`; `--json` is a `confirmationRequired` `CommandError` with that `Confirmation`. Running the printed command stops the fixture (`exited`, exit 0, `SIGTERM`, `lsof` shows no port). |
| `stop::a_term_ignoring_fixture_is_forced_only_after_a_still_running_stop` | Force needs a prior `stillRunning` on the same instance: `force` first is `forceNotOffered` (exit 3, fixture untouched) and names the stop to run; the stop exits 1 with `stillRunning` and the exact `forceCommand`, and nothing escalates; that command then exits 0 with `exited` and the fixture died of `SIGKILL`.                                                                                                                               |
| `stop::a_stale_identity_or_port_set_is_refused_with_the_current_command`  | Every port must be confirmed, and a replaced process is never signalled: one of two ports is `stale`/`portsChanged` (exit 3) with the full command; after the test restarts its fixture on the same port, the old identity is `stale` and the refusal names the new process's command; both fixtures are untouched.                                                                                                                                   |
| `stop::kosse_itself_is_refused`                                           | Never Kossé itself: its identity and ports exit 3 `actionRefused` with `refused`/`kosseItself`; its port as target suggests no command; the instance still serves with the same start time.                                                                                                                                                                                                                                                           |
| `stop::a_respawn_is_reported_as_a_negative_outcome`                       | A supervised child's stop reports `respawned` (exit 1) with the supervisor as parent; the child exited and the supervisor (the parent) was never signalled.                                                                                                                                                                                                                                                                                           |
| `stop::without_an_instance_nothing_is_signalled`                          | D1: without a verified instance on `--instance-port`, exit 4 (`noInstance` with `--json`), the message names `kosse serve --no-open --port <n>`, and the fixture is untouched.                                                                                                                                                                                                                                                                        |

The existing `actions.rs` suite still covers the server side (revalidation, test scope, offers used once, `endpointTaken`, `shared`, token and rate limits), which the CLI reaches unchanged.

## Manual agent flow on fixtures

Two owned `kosse-fixture` processes (A on two ports, B ignoring `SIGTERM`) and a debug `kosse serve --no-open --port 47901 --probe-only= --act-only=<A>,<B>`, `KOSSE_CONFIG_DIR=/var/empty/kosse-tests`, run from `/`. `<repo>` replaces the fixtures' working directory.

```text
$ kosse stop 61000 --instance-port 47901
kosse: port or PID 61000 matches 1 process; stop takes the identity <pid>.<start> and --ports with every port it listens on, so nothing was signalled. To confirm one:
  kosse stop 80215.1793289956 --ports 61000,61001 --instance-port 47901  (kosse-fixture, <repo>)
exit 3
$ kosse stop 80215.1793289956 --ports 61000 --instance-port 47901
kosse: process 80215.1793289956 does not listen on exactly the ports 61000; nothing was signalled. To confirm what runs now:
  kosse stop 80215.1793289956 --ports 61000,61001 --instance-port 47901  (kosse-fixture, <repo>)
exit 3
$ kosse force 80218.1793289956 --ports 61002 --instance-port 47901
kosse: force is offered only after a `kosse stop` of the same identity and ports ended stillRunning on this instance, for 60 s and once; nothing was signalled. Stop it first:
  kosse stop 80218.1793289956 --ports 61002 --instance-port 47901  (kosse-fixture, <repo>)
exit 3
$ kosse stop 80218.1793289956 --ports 61002 --instance-port 47901
outcome: stillRunning
process: 80218.1793289956 (still running; it may ignore SIGTERM)
ports: 61002

$ kosse stop 80215.1793289956 --ports 61000,61001 --instance-port 47901

ports: 61000, 61001 (free)

$ kosse force 80218.1793289956 --ports 61002 --instance-port 47901 --json

{"error":"stale","message":"process 80218.1793289956 has already exited; nothing was signalled.","result":{"outcome":"stale","reason":"exited"}}
```

After stopping that server: `kosse stop 1.1 --ports 1 --instance-port 47901 --json` printed `{"error":"noInstance","message":"no Kossé instance runs on 127.0.0.1:47901; stop and force act only through one, which keeps the force offer: start `kosse serve --no-open --port 47901` (or the menu-bar app) and retry"}`, exit 4. The `--json` answer above is shown on one line; the CLI pretty-prints it.

## Not verified

- Against the resident menu-bar app (rather than `kosse serve`): same API and guard, not exercised here.
- A `permissionDenied`, `signalFailed`, `observationFailed` or `internal` outcome through the CLI: no fixture produces one; their mapping is in `stop.rs` and the server side is unchanged.
- `rateLimited` is exercised only as the test helper's retry condition, not asserted as an outcome.
