## Decisions

- **Plist written by hand, not `auto-launch` 0.6.0 or `service-manager` 0.11.0** (read on docs.rs): `auto-launch` only writes/deletes `~/Library/LaunchAgents/<name>.plist` and never loads it; `service-manager` uses the legacy `launchctl load`/`unload`/`remove`; neither lets tests redirect the agents directory. The plist is ~20 lines with XML escaping, `launchctl bootstrap gui/<uid>` / `bootout gui/<uid>/com.davidpp.kosse` is the supported interface (launchctl(1)). No new crate; `rustix::process::getuid` (rustix already in the graph via core) for the domain.
- **Agent content:** `ProgramArguments = [<this kosse>, --no-open]`, `RunAtLoad`, `LimitLoadToSessionType = Aqua` (no tray from an SSH login), `ProcessType = Interactive`, **no `KeepAlive`** (Quit stays quit until next login). `enable` is idempotent (identical plist + loaded = no-op), removes the plist again if `bootstrap` fails, and notes when the binary lives in `target/`. `status` reads the program through `plutil -extract`, so a hand-edited or binary plist still reads.
- **Test injection:** agents directory = `$HOME/Library/LaunchAgents` (tests set `HOME`), and the debug-only `KOSSE_TEST_LAUNCHCTL` replaces `/bin/launchctl` (same pattern as `KOSSE_TEST_OPENER`; compiled out of release).
- **Doctor** checks: platform, binary + the `kosse` on `PATH`, config (parse via `CentralStore::load`, permissions), port (`instance::find`: socket owner first, then GET to a verified Kossé only), git (developer dir), lsof (info only: Kossé does not use it), startup, GUI login (owner of `/dev/console` is this user; `launchctl managername` was rejected because it reports `Background` from agent shells where the tray still works). Exit 1 only on a `fail`.
- **cargo-auditable 0.7.7** (cheap: +~50 KB with the other S09 code, a `.dep-v0` section verified with `otool -l`) so `cargo audit bin`/SBOM scanners can check the shipped file. **cargo-about 0.9.2** (0.9.3 was 2 days old, inside the release-age policy). Both pinned in `mise.toml` via the GitHub backend.
- **Probing in the sandbox run:** the release binary has no `--probe-only`, and the invariant forbids tests probing real services. `test:package` runs every scanning `kosse` under `sandbox-exec` with `(allow default)(deny network-outbound (remote ip "*:*"))(allow network-outbound (remote ip "localhost:<fixture port>"))`. The run proves it holds: a second fixture in the same project, outside the allowance, gets probe result `refused`. Process discovery itself is read-only (unchanged).
- **No `.app` bundle:** S08 showed the status item and web view start from the bare executable; the installed app started (`mode: resident`) and quit cleanly here.
- **Install by rename** (temp file in the destination directory, then `rename`) so a running Kossé keeps its file and no signed executable is modified in place. `--purge` removes only `config.json` and `config.lock` at the path the installed `kosse config path` prints, then the directory if empty.
- **Upgrade = same-version rebuilt archive**: there is no second version to install; the test installs the archive, saves a profile, rebuilds with `release:local` (different archive SHA-256) and installs over it.

## Review fixes (after the first report)

- **Ownership by content, not path:** a recorded file is install:local's only while its SHA-256 matches the record. Install refuses to replace a changed one (exit 1), uninstall keeps it and reports it (exit 0, still recorded); `--force` overrides both. A file with no record is never replaced or removed, even with `--force`.
- **No leaked scratch directories:** `fail()` now throws a `Refusal`; `script()` prints its message and sets the exit code after every `finally` has run (usage errors exit 2). Earlier runs had left 3 `kosse-install-*` directories in `$TMPDIR`; they were removed, and test:package now checks none appears.
- **Interrupted installs recoverable:** the record is rewritten (temp file + rename) after each created directory, each placed file and each removed stale file, so it always names what is on disk.
- **Malformed input:** an install record that is not JSON or fails validation, or a manifest that is not JSON, gives a message instead of a stack trace. `createdDirs` entries are validated like file paths (relative, no `..`, `.` only for the prefix itself). An agent plist without a readable `ProgramArguments.0` makes uninstall refuse ("inspect it with `kosse startup status` or run `kosse startup disable` first"). The startup guard compares the agent's program and the installed binary by device and inode after resolving links.
- **Startup replacement:** `enable` over a loaded agent of another binary boots it out, then bootstraps with up to 3 retries 300 ms apart on launchd's exit 5 (EIO, typical while the old job is torn down). If bootstrap still fails, the error says the previous agent was unloaded and startup is now off.
- **test:package and the real launchd domain:** `startup status` and doctor's startup level accept `disabled, but launchd still has …` / `warn`, which a really enabled Kossé agent on the test machine would produce (the query is read-only).
- **Notices:** tailwindcss's license is appended to the web section (it generates part of the shipped CSS, which Vite's JS license collection misses). release:local first parses `about.toml` and `deny.toml` (Bun's TOML parser) and fails unless the allow-lists and per-crate exceptions are identical (shown failing with an extra license added to option-ext). It then checks structurally that option-ext is listed under the MPL-2.0 section, ring/rustls-webpki/untrusted under ISC, and tao and wry under Apache-2.0.
- **Docs:** the README and INSTALL.md archive steps now extract first and install from the extracted directory, and add the `~/.zprofile` PATH line. INSTALL.md gains the Homebrew notes and a corrected uninstall order. The formula caveats cover enabling startup from `HOMEBREW_PREFIX/bin` (`current_exe` keeps the symlinked path, verified) and disabling it before `brew uninstall`. The formula homepage is now `github.com/davidpp/kosse`, and its `version` line is kept with a comment explaining why. The README now says how to try the formula in a personal tap. Doctor's lsof line now reads "optional". The `cargo install` route in the architecture document is marked as a possible later one.

## Unverified, deferred, approval gates

- **Real login cycle: not run (approval gate).** No real agent was written and `launchctl bootstrap` was never called on the real domain. Human steps, after `bun run release:local && bun run install:local`: (1) `~/.local/bin/kosse startup enable` → the menu-bar icon appears without a window; `kosse startup status` → `enabled at login: … (loaded, running as PID …)`. (2) Log out and back in → the icon appears without a window, one instance (`kosse doctor` port line names a `resident` Kossé). (3) Quit from the menu → it stays quit (no KeepAlive). (4) `kosse startup disable` → `startup disabled`, plist gone, `launchctl print gui/$(id -u)/com.davidpp.kosse` fails. (5) `bun run uninstall:local`.
- **Browser-download quarantine: documented, not exercised.** Setting `com.apple.quarantine` and launching would raise a Gatekeeper dialog on the desktop, which tests must not do. `INSTALL.md` and the README describe the refusal and `xattr -d com.apple.quarantine kosse` with a trust warning.
- **Unsigned/unnotarized** by design (ad-hoc linker signature only); signing, notarization, a tap and any public release remain approval-dependent work.
- **Homebrew formula**: generated and syntax-checked (`ruby -c`) only. `brew install`/`brew audit` were not run: they need a tap and would change the real Homebrew installation.
- **Tray look/clicks and visible window**: still S08's human checklist; this run only showed the installed app reaches `resident` and quits.
- **Not reproducible byte-for-byte**: file mtimes and gzip headers differ per build (the upgrade test relies on that difference); `MANIFEST.json` records commit and dirty state instead.
- **CI**: the new `test:package` and upload steps have not run on GitHub yet (nothing pushed); `cargo about` may contact the network there to fetch license files missing from crate packages.
