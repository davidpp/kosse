## Command syntax and columns settled on

```text
kosse list [--here | --project <dir>] [--port <n>] [--service <id|name>] [--json] [--instance-port <port>]
kosse url  <service|port> [--here | --project <dir>] [--json] [--instance-port <port>]
kosse port <n> [--json] [--instance-port <port>]
```

Service table (one row per port): `PROJECT` (name, `/<package path>` below the root), `BRANCH`, `SERVICE` (`Name (id) [source]`, `ambiguous: a, b`), `PORT`, `HTTP` (`<status> <url>` or the probe state), `PROCESS`, `PID.START` (the identity S17's `stop` will take), `AGE`. `## Configured, not observed`: `PROJECT` (root), `SERVICE`, `SOURCE`, `MATCH`. Exit codes: 0 answered, 1 negative (`notFound`, `ambiguous`, `noHttp`), 2 usage (clap), 3 refused (`notInProject`), 4 could not observe (`projectUnknown`, `scanFailed`, `configUnavailable`, `outputFailed`).

## Decisions and deviations

- **`list --port` now filters; the instance to ask is `--instance-port`.** The blueprint gives `--port <n>` to the service filter, which collided with `list`'s existing instance-port flag. Pre-1.0, recorded under Changed in the changelog; every in-repo caller (`app.rs`, `probe.rs`, `profiles.rs`, `redaction.rs`, `list.rs`, `scripts/package-test.ts`) updated. `doctor --port` is unchanged.
- **`url` prints the root URL only.** The blueprint's "(the profile's probe path when declared)" conflicts with the AGENTS.md invariant that the only URLs emitted are `prober::open_url`'s `http(s)://localhost:<port>/`; the invariant wins, and `url` builds its output with `prober::open_url` from the endpoint's TLS flag and port. Callers append paths (`"$(kosse url web)health"`).
- **`url` reads existing probe results; it requests none.** The blueprint's Security section says `url` uses requested probes. S13 answers from the snapshot only: with an instance, automatic probes cover the user's own project processes; without one, `url` says that a one-shot scan never probes. Requested probes from the CLI (`POST /api/probe` with the session token) arrive with `wait --http` in S14; `url` can adopt them then.
- **Bind addresses left the table** (few columns); they and `exposure` stay in `--json`.
- **`port` exits 0 for both free and taken** (it answered). The blueprint's `--free` assertion (exit 1 when taken) is not in S13's scope.
- **`--project <dir>`** accepts a root as printed (also a saved profile's root whose directory no longer exists) or any directory inside a project, resolved like `--here`.

## Unverified or limited

- clap usage errors (exit 2) print clap's text even with `--json`, not a `CommandError`.
- Profile names refuse control characters, and Git cannot describe a worktree whose path holds a newline (attribution reports the project as unknown), so the newline case of the hostile-table test comes from the process name.
- `port`'s answer is as old as the snapshot (up to one scan interval with an instance; `scannedAtMs` says when).
- No real-agent session was run (S19).
