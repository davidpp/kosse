## Decisions

- **Matching never crosses projects.** Only services attributed to a root are candidates for its entries, so `match.port` alone cannot claim another project's process.
- **`match.cwd` never looks outside the project.** It is resolved one component at a time with `symlink_metadata`/`read_link` from the canonical root; a link or `..` that would leave it stops the walk (`profileMatchOutsideProject`) before anything outside is stat-ed. An absolute link target counts as inside only when it starts with the canonical root. `..` in the profile itself is refused at validation.
- **Ambiguity is visible.** A process matching two entries is `ambiguous: [ids]` and gets neither label.
- **A repository file cannot steer probing** (product decision after review):
  - only the central, user-authored profile's `protocol: http|https` lifts `knownNonHttpPort`/`knownNonHttpProcess` (owner and loopback rules still apply); a repository's `protocol` is shown, never acted on;
  - a `probePath` (from either source) is requested only after a plain `GET /` on that identity and port got an HTTP response; until then, and again after a failed `GET /`, probes request `/`.
- **Probe paths** are RFC 3986 path and query characters or `%XX` only, a strict subset of what `http::uri::PathAndQuery` accepts (`<`, `>`, `` ` ``, `"`, `{`, `|`, `^`, `[` refused). The prober re-checks before connecting; a path it cannot send is the terminal `invalidPath`, never a protocol failure that would retry over TLS.
- **`match` merges as one value**, not per criterion. Unknown `match` criteria are refused (ignoring one would widen a match); unknown fields elsewhere are kept, per service ID and per link by URL.
- **A repository file is refused as a whole** on any rule violation; the last good one stays.
- **Repository files are opened with `O_NOFOLLOW | O_NONBLOCK`**, then `fstat`-checked against the inode that was checked, so neither a swapped-in link nor a FIFO can redirect or block the scanner.
- **Central file:**
  - a corrupt, invalid, `version` < 1 or newer file (or one with a nested profile from a newer Kossé, reported as `newerVersion`) refuses every write and is left byte-for-byte (`409 configUnavailable`);
  - a symbolic link stays a link: the target is resolved and replaced in its own directory; a dangling link is refused;
  - roots are canonicalized on save; hand-edited non-canonical keys that can never match are reported (`profileRootNotCanonical`);
  - 64 KiB, as for repository files; a save that would exceed it is refused.
- **`POST /api/profile`** accepts only roots in the snapshot or already saved, and has its own one-per-second limit (separate from refresh, probe and stop). Write failures are `500 configWriteFailed`.
- **`EffectiveLink.kind` is display only**: trust comes from `reach` and the visible `host`, since a repository can label an external host `local`.
- **No directory crate**: std `home_dir()` + `Library/Application Support/Kosse`.

## Commands run

All from the repository root.

- `bun run check` passes: fmt, oxlint, clippy `-D warnings`, tsc ×2, vitest 7/7, vite build, budget, nextest **178/178** (S05's suites included), doc tests, release build. It leaves the tree unchanged.
- `cargo deny check`: `advisories ok, bans ok, licenses ok, sources ok`.
- `cargo nextest run --workspace -E 'binary(profiles)'` (12 tests: the real `kosse` binary, temporary Git repositories, owned fixtures, a temporary `KOSSE_CONFIG_DIR`):
  - **Central over repository with provenance** (`list --json` and table): `web` is `Central Web` (source central) with the repository's match, probe path and links; `http://localhost:3001/docs` is `loopback`, `https://acme.local/` with `kind: local` is `declared`; `api` (no process) is listed under `CONFIGURED, NOT OBSERVED`. `git status --porcelain` and the file are unchanged.
  - **Matching never leaves the project:** two processes in one directory both match, each its own identity; a link inside resolves; a link to another repository warns and matches nothing; a port-only entry naming another project's fixture port leaves it unlabeled; two entries on one directory give `ambiguous: one, two`.
  - **Hostile repository files:** a `javascript:` link, `../` in `match.cwd`, duplicate IDs, `version: 2`, 70 KiB and a symbolic link each give `profileUnusable` and no label.
  - **Inert data:** a profile whose `$schema`, an `extends` key and a link point at a TCP listener the test owns, plus `scripts`/`command` fields, is applied by `list` and `serve`; no connection arrived and nothing ran.
  - **Customize writes only central configuration:** no token or cross-site → 403, unknown root → 404, nothing written; a save labels the fixture (source central), dir 0700, file 0600; a `javascript:` link → 422 naming the field, file unchanged; `null` removes it. The repository's `git status` and every file's size and mtime are unchanged.
  - **Reload:** truncated JSON and `version: 3` keep the last good profile with a warning; deletion removes it without one; recreation applies.
  - **Central problems:** truncated and `version: 9` files are reported and refuse saves (409), byte-for-byte unchanged; after deletion a save writes a fresh file.
  - **Probing on a repository's word:** a fixture named `postgres` with a repository `kosse.json` declaring `protocol: http` and `probePath: /healthz?ready=1` stays `knownNonHttpProcess` and receives nothing for 4 s; after a central `protocol: http`, the automatic probe sends `GET / HTTP/1.1` (404, verified HTTP) and the next one ("try HTTP") sends `GET /healthz?ready=1 HTTP/1.1`.
  - **Moved project:** the process in the new directory is unlabeled and the old profile shows `(project not observed)` until `kosse config move`; repeating it exits 1.
  - **Worktrees:** each worktree reads its own `kosse.json`; a central profile on the linked worktree applies only there.
  - **Non-canonical central key** (`/var/…` for `/private/var/…`): `profileRootNotCanonical`, no label.
  - **`kosse config`:** `schema` equals the committed file; `path` creates nothing; a relative `KOSSE_CONFIG_DIR` exits 1.

## Measurements

- `cargo nextest run --workspace -E 'binary(profile_cost)' --no-capture` (30 owned fixture listeners in 10 repositories, each with a central profile and a `kosse.json` naming three services, all matched every scan): first apply (reads 11 files) **1.10 ms**; warm median **0.43 ms** over 20 scans, next to a median scan of 5.8 ms (about 0.01 % of the 3 s cadence). The test fails above 30 ms.
- Steady state: at most one `stat` per profile file per second, plus the `match.cwd` walk per configured entry and a `canonicalize` per service cwd in a profiled project, per scan.

## Unverified or deferred

- **UI.** "Customize this project" exists as the guarded API and contract only; the form, provenance display and the one `http(s)`-only link builder are S07.
- **Repository export** is not implemented; nothing in Kossé writes into a project.
- **`kosse list` against a running instance** still scans itself (S08).
- **Mid-write reads.** A hand edit saved non-atomically can be read half-written; it is reported as invalid and the last good version stays until the next check.
- **Lock scope.** The advisory lock serializes Kossé writers (dashboard and CLI), not an editor saving at the same moment.
- **Probe path state** is not in the snapshot: an endpoint's `http` does not say whether `/` or `probePath` produced the result.
- **Merge with S05.** Rebased onto `7806e76`; conflicts in `api.rs` (`AppState::new` gained `actions`), `server.rs`, `main.rs`, `lib.rs`, `contract.rs`, `Cargo.toml`/`Cargo.lock`, `crates/core/Cargo.toml`, `tests/support/mod.rs`, `CONTRIBUTING.md` and the generated `contracts.ts` were resolved keeping both features.
