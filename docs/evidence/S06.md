## Decisions

- **Matching never crosses projects.** Only services attributed to a root are candidates for that root's entries, so `match.port` alone cannot claim another project's process. `match.cwd` is resolved with `canonicalize` and must stay under the canonical root, so a symbolic link out of the project matches nothing and warns (`profileMatchOutsideProject`); one that stays inside works. `..` is refused at validation.
- **Ambiguity is visible.** A process matching two entries gets `ambiguous: [ids]` and neither label; no specificity tie-break. Each matching entry still lists it in `matched`, so an entry is "configured, not observed" exactly when nothing matches it.
- **`match` merges as one value**, not per criterion: a central `port` combined with a repository `cwd` would describe neither entry. Other fields merge individually; `links` replaces. Recorded in project-metadata.md.
- **Unknown `match` criteria are refused**, unknown fields elsewhere are kept: ignoring an unknown criterion would widen a match, an unknown display field is harmless.
- **A repository file is refused as a whole** on any rule violation (the last good one stays), never partly applied.
- **Corrupt or newer central file: refuse writes, never back up and replace.** The original stays the recoverable copy; the API answers `409 configUnavailable` naming the file. Simpler and safer than moving the user's hand edit aside.
- **64 KiB for both files** as the blueprint says; a save that would exceed it is refused (`409`), so the file never becomes unreadable by its own writer.
- **Declared HTTP.** A matched service with `protocol: http|https` lifts `knownNonHttpPort`/`knownNonHttpProcess` skips to `pending`, restricted again by the owner rule; `notOnLoopback` and `otherUser` are never lifted. Its `probePath` replaces `/` in the request line; the response URL stays `http(s)://localhost:<port>/` (`prober::open_url` unchanged).
- **The save route only accepts known roots**: a project in the current snapshot or a root already saved, so the API cannot plant profiles for arbitrary paths.
- **Config directory without a dependency**: std `home_dir()` + `Library/Application Support/Kosse` (macOS only in v1); `dirs`/`directories` would add a crate for one path.
- **ts-rs `no-serde-warnings`**: ts-rs printed a build-time warning for `deserialize_with` (the duplicate-key check), which it does not need.

- `bun run contracts` regenerates `web/src/generated/contracts.ts` and `docs/kosse.schema.json`; both freshness tests pass on the committed files.
- `cargo nextest run --workspace -E 'binary(profiles)'` (11 tests, the real `kosse` binary, temporary Git repositories, owned fixtures, `KOSSE_CONFIG_DIR` in a temporary directory), run three times back to back, all green:
  - **Central over repository with provenance** (`list --json` and table): a committed `kosse.json` names `web` and `api`; a central profile renames `web`. `web` is `Central Web` (source central) with the repository's match, probe path and links (source repository); `http://localhost:3001/docs` is `loopback`, `https://acme.local/` with `kind: local` is still `declared`. `api` has no process: listed under `CONFIGURED, NOT OBSERVED` with its source and match. `git status --porcelain` and the file are unchanged.
  - **Matching never leaves the project:** two processes in `apps/web` are both `web`, each its own identity; a symlink inside the project resolves; `apps/escape` → another repository matches nothing and warns `profileMatchOutsideProject`; `match: {port}` set to another project's fixture port leaves that process unlabeled and the entry unobserved; two entries on one directory make the process `ambiguous: one, two` (table too).
  - **Hostile repository files** (one-shot `list`, so no last good version): a `javascript:` link (`services.web.links[0].url`), `../` in `match.cwd`, duplicate service IDs, `version: 2` (`newerVersion`), 70 KiB (`tooLarge`) and a symbolic link to a valid file elsewhere (`notAFile`) each give a `profileUnusable` warning, no metadata and no label.
  - **Profiles are inert data:** a valid profile whose `$schema`, an `extends` key and a link point at a TCP listener the test owns, plus `scripts`/`command` fields that would create a marker file, is applied by `list` and by `serve`; the listener accepted **no** connection and the marker does not exist.
  - **Customize writes only central configuration** (`serve`): `POST /api/profile` without token → 403, cross-site → 403, unknown root → 404 `unknownProject`, with nothing written; a save → 200 and the next snapshot labels the fixture with source central; the directory is 0700 and the file 0600; a `javascript:` link → 422 `invalidProfile` naming the field, file bytes unchanged; `profile: null` removes it. `git status --porcelain` and every file's size and mtime in the repository are unchanged.
  - **Reload** (`serve`): valid → applied; truncated JSON → `invalid` warning with `lastGoodRetained: true` and the label kept; `version: 3` → `newerVersion`, last good kept; deleted → no profile, no warning; recreated → applied.
  - **Central problems** (`serve`): a truncated and a `version: 9` central file are each reported, `POST /api/profile` → 409 `configUnavailable`, the file is byte-for-byte unchanged; deleting it clears the warning and the next save writes a fresh file.
  - **Declared HTTP and probe path** (`serve --probe-only=<fixture>`): a fixture named `postgres` (otherwise `knownNonHttpProcess`) in a project whose `kosse.json` declares `protocol: http`, `probePath: /healthz?ready=1` is probed; its recorded request line is `GET /healthz?ready=1 HTTP/1.1`. Without the file it is skipped again.

  - **`kosse config`**: `schema` output equals `docs/kosse.schema.json`; `path` prints `$KOSSE_CONFIG_DIR/config.json` and creates nothing; a relative `KOSSE_CONFIG_DIR` exits 1.

## Measurements

- `cargo nextest run -p kosse-core --test profile_cost --no-capture` (30 owned fixture listeners in 10 repositories, each with a central profile and a `kosse.json` naming its three packages' services, all 30 matched in every scan): first apply (reads 11 files) **1.22 ms**; warm median **0.63 ms** over 20 scans next to a median scan of 6.1 ms, about 0.02 % of the 3 s cadence. The test fails above 30 ms.
- Steady state costs one `stat` per profile file per second at most (central file plus one `kosse.json` per observed project), plus a `canonicalize` per configured entry and per matched-project service cwd per scan.

## Unverified or deferred

- **UI.** "Customize this project" exists as the guarded API and contract only; the dashboard form, provenance display and link rendering (one `http(s)`-only link builder) are S07. Links are validated server-side regardless, since Redact does not neutralise `javascript:` URLs.
- **Repository export** (writing a `kosse.json` on explicit request) is not implemented; nothing in Kossé writes into a project.
- **`kosse list` against a running instance** still scans itself (S08); it applies the same profiles.
- **Mid-write reads.** A hand edit saved non-atomically can be read half-written; it is reported as invalid and the last good version stays until the next check. Kossé's own writes are atomic.
- **Lock scope.** The advisory lock serializes Kossé writers (dashboard and CLI); an editor saving the file concurrently is not locked out, and the later write wins.
- **Merge with S05**: shared files touched are listed in the final report; the tree was not integrated with S05.
