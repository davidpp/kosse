# S01b evidence: slim web runtime and bundle budget

Recorded 2026-10-28 on macOS 26.6.2 (25G83), arm64, mise 2026.10.11, Chrome 156 (headless only).
The final runs were made on a tree rebased onto `0f4177a` (S03 plus the dashboard-window direction
docs). The tree fingerprint is the commit that adds this file on top of `0f4177a`: these results
describe that commit's content. "Unchanged tree" below means an identical content hash
(`git ls-files -co --exclude-standard | sort | xargs shasum | shasum`) before and after a command.
Every row in "Commands run" ran on that content unless it says otherwise. Only this file and
orchestrator-owned docs changed afterwards.

## What changed

- **Runtime.** The web app keeps React APIs and imports (`react`, `react-dom/client`), but the
  [TanStack Redact](https://tanstack.com/redact/latest/docs/overview) Vite plugin swaps the runtime
  in the build, the dev server and Vitest. `react` and `react-dom` stay installed, as
  [Redact's installation guide](https://tanstack.com/redact/latest/docs/installation) asks: they
  are peers of TanStack Query and Testing Library and supply the types. Neither ships. The license
  notice in `web/dist/.vite/license.md` lists only query-core, react-query, redact (MIT) and
  lucide-react, and the bundle has no React-only markers (`Minified React error`,
  `__CLIENT_INTERNALS…`).
- **Removed.** `@base-ui/react`, `@fontsource-variable/geist`, `class-variance-authority`, `cn`,
  `shadcn`, `tw-animate-css`, `@tanstack/react-router` and `@tanstack/router-plugin`, plus
  `web/components.json`, the shadcn button, `web/src/lib/utils.ts`, `web/src/routes/*` and
  `web/src/routeTree.gen.ts`. A clean `bun install` installs 134 packages (S01: 450).
- **Router dropped** (measured below). `web/src/app.tsx` renders the single view at `/` and
  `/index.html` (`viewFor`, unit-tested), and an honest not-found for any other path.
- **Styles.** `web/src/styles.css` is a closed, `static` token set (`--color-*: initial`, every
  role emitted in both schemes, all values inside sRGB):
  - cool-tinted neutrals, a `line-strong` control border (at least 3:1), and one accent for
    focus and selection;
  - observation roles (`reachable`, `stale`, `failed`) for markers and icons only;
  - a `text-data` size, a system font stack, light/dark from `prefers-color-scheme`, themed browser
    surfaces, and reduced motion.

  The health page was restyled with these tokens. While a refetch runs, Retry is `aria-disabled`:
  it stays focusable and a guard ignores clicks and keys (unit test). Tailwind scans only
  `web/src` (`source(".")`). With automatic detection, words in `web/DESIGN.md` had generated
  extra CSS rules.

- **Budget.** `scripts/bundle-budget.ts` (`bun run budget`) gzips every `.js`/`.mjs`/`.css` file
  under `web/dist` separately (zlib default level, the same as Vite's report) and sums the results.
  It fails in four cases:
  - over 50 kB (decimal, Vite's unit);
  - a font file (`.woff`/`.woff2`/`.ttf`/`.otf`/`.eot`);
  - `@font-face` in shipped CSS (data-URI fonts);
  - a missing or empty build.

  `test` (and therefore `check` and CI) and `build` run it right after `vite build`.

- **Lint guard.** `.oxlintrc.json` `no-restricted-imports` rejects `hydrateRoot` and `Activity`,
  whose Redact features are compiled out. Verified on a probe file: both imports were reported,
  then the file was deleted.
- **Impeccable context.** `web/PRODUCT.md` (init) and `web/DESIGN.md` (the built token foundation
  and the observation-state model, marked provisional). See "Design context" below.
- **Docs.** AGENTS.md, CONTRIBUTING.md, README.md, `blueprint/architecture.md` and
  `blueprint/references.md` now record the outcome: no Router, the budget command, Redact as the
  runtime, and the `javascript:` URL rule.

## Decisions

- **Redact 0.2.1, pinned exactly, through an owner-approved release-age exception.** Releases up
  to 0.1.5 declare no license: 0.1.4 has no `license` field and no LICENSE file, and Vite's notice
  listed it without one. 0.2.1 (published 2026-10-27) is the first MIT release, and it falls inside
  the 5-day `minimumReleaseAge` until 2026-11-01. The owner approved an exception for exactly that
  version.

  Bun 1.4.2 (pinned) does not honour version-scoped `minimumReleaseAgeExcludes` entries, so the
  maintainer applied a bare-name entry for the single command
  `bun add --cwd web --exact @tanstack/redact@0.2.1`, then restored the scoped entry.
  `bunfig.toml` records the approval. Its entry exempts nothing on Bun 1.4.2, and the exact pin in
  `web/package.json` and `bun.lock` fixes the version. A clean `bun install --frozen-lockfile`
  passes with no broader exception, and the global guard is unchanged.

  0.2.1 checks:
  - Vite's notice reads `@tanstack/redact - 0.2.1 (MIT)`.
  - Every peer dependency is optional.
  - Plugin presets and feature names are the same as in 0.1.4.

- **Feature flags.** `redact({ features: { hydration: false, activity: false, fragmentRefs: false } })`.
  The app mounts with `createRoot`; with hydration off, `hydrateRoot` throws. Neither the app nor
  Query or Lucide uses `<Activity>` or Fragment refs (checked by searching their ESM builds; the
  lint rule keeps it that way). Suspense, lazy, class components (error boundaries), memo,
  forwardRef, context and portals stay on for S07.
- **Lucide.** Named per-icon imports from `lucide-react` (`sideEffects: false`); only the icons in
  use ship.
- **Vitest runs Redact.** By default Vitest leaves dependencies to Node, which loads real React for
  them. Two settings in `web/vite.config.ts` fix that:
  1. `test.server.deps.inline: true` sends every dependency through Vite, where the aliases apply.
  2. `environments.client.resolve.mainFields` is restated to Vite's own client defaults. Vitest
     clears `mainFields`, which resolves Testing Library to its CommonJS build, and that build's
     `require("react")` skips the aliases. The build output is unchanged.

  `src/runtime.test.tsx` guards both, under StrictMode, through Testing Library:
  - a plain component must render once (development React renders twice);
  - a probe drives Query's `QueryClientProvider` + `useQuery` and a Lucide icon. A second copy of
    React in any of them throws on its hooks.

- **Testing Library under Redact.** Rendering, role queries, jest-dom, `user-event` clicks and
  keys all work. Since 0.2.0, `act` flushes queued renderer work and effects as React's does. The
  tests never depended on the 0.1.x microtask-only `act`.
- **`javascript:` URLs (security difference).** React 19.3's DOM client replaces a `javascript:`
  `href` with a URL that throws ("React has blocked a javascript: URL"). Redact renders it
  verbatim: `<a href="javascript:alert(1)">` kept that `href` in a Testing Library probe on 0.2.1.
  `blueprint/architecture.md` (API and browser security) now requires one link builder that accepts
  only `http:`/`https:` for every rendered link (S07), with CSP (S04) as the backstop.

- The 127.98 kB baseline is JS + CSS, the metric the budget counts. The plan's "~103 kB" for S01 was
  the main JS chunk alone (103.26 kB; the route chunk adds 19.62 kB and CSS 5.09 kB).
- The 0.1.4 rows share one app revision. The 0.2.1 rows use the final app code. Its `static` theme
  and new roles add about 0.1 kB of CSS over the 31.14 kB measured just before them.
- The shipped build is `index-*.js` (27.89 kB gzip, 78.42 kB raw) and `index-*.css` (3.40 kB gzip,
  11.62 kB raw), with no fonts. The release binary is 1.60 MB (S01: 1.8 MB).

**Router decision.** TanStack Router alone costs about 28.2 kB gzipped (58.58 − 30.37, both 0.1.4 with the same UI),
so even the trimmed runtime with Router is over budget before S07 adds a single row.
It was removed; S07 keeps 18.7 kB of headroom. Addressable views (inspect, window routes for S08)
use a minimal `location`/`history` switch (S07). Router was not re-measured on 0.2.1 because it is
uninstalled, and its own size does not depend on the Redact version.

The server sends assets uncompressed (rust-embed, loopback). Gzip is the budget's metric, not what
goes over the wire; the raw bytes are listed alongside it.

## Design context

The Impeccable `init` step wrote `web/PRODUCT.md`, the product record, derived from README.md,
`blueprint/product.md`, `blueprint/architecture.md` and the slice brief. The primary surface is
Stackscan's own WKWebView window opened from the tray, with any browser as the secondary path. The
owner was not interviewed in this session; inferred facts are marked `(inferred)` for confirmation
in S07.

`web/DESIGN.md` records the built token foundation (Stitch DESIGN.md format, marked provisional) and
the observation-state model:

- separate listening and reachable states;
- ended and disconnected treatments;
- colour for markers only, plus a marker-shape vocabulary so no state relies on hue.

It also lists the roles S07 still has to decide with the owner: selected row, keyboard hint, row
metrics, and a destructive-action role.

Impeccable's visual-direction round (concept seeding and a decision page with the owner) was not
run. It needs the owner and would open a browser on the desktop, so it belongs to S07. No
`.impeccable/` sidecar was written.

## Unverified or open

- **Remove the release-age exception after 2026-11-01** (tracked by the maintainer). Bun 1.4.2
  cannot apply version-scoped entries, so another Redact add or update before then needs the
  maintainer again.
- **`javascript:` URLs.** Neutralizing them is now an S07 requirement (link builder), with CSP from
  S04. Nothing renders process-derived links yet.
- React DevTools with Redact (the 0.2.x docs list inspection support) was not exercised.
- `bun run dev` was checked for render and proxy only; Fast Refresh with edits was not exercised.
- True phone width (390 px) is unverified. Keyboard focus retention on Retry is unit-tested; there
  was no full keyboard pass.
- The budget applies to gzip, which is not what the server sends.
