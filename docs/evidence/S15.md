| `profile_authoring::a_dry_run_predicts_what_the_running_instance_applies`       | The dry run's match table (including an ambiguous process and an entry matching nothing, exit 1) equals the running instance's next snapshot after `set`, process by process and entry by entry. | `profile_authoring::revisions_refuse_a_lost_update_between_the_cli_and_the_api` | The precondition works in both directions: a CLI set or remove from a stale revision is refused (exit 3, `revisionConflict`), and so is an API save (`409 revisionConflict`). The file is unchanged each time, and API clients that send no revision keep working. The API rate limit is respected by retrying on `429`, with no fixed sleep.                                                               |

## Unverified and deviations

- `--file -` reads standard input. The blueprint wrote `(--file <path> | -)`, and a bare `-` positional would clash with `<root>`. The blueprint now says `--file <path | ->`.
- A directory outside any project gives exit 2 (usage), unless a central profile is saved for exactly that path. S13's `--here` should use the same code; this needs coordinating at merge.
- `profile.rs` copies `list.rs`'s instance-or-scan-once helpers (S13 owns `list.rs`). Fold them into one helper after the merge.
- The JSON records have a `schemaVersion` but no generated schema file yet. That waits for S13's mechanism for agent records. The CLI error shape `{error, message, problems?}` is a local type in `profile.rs`.
- The dry run reads the repository `kosse.json` freshly. A running instance keeps the last good version when the file turns invalid, so the two can differ only while a repository file is invalid. Context reports that state as a problem.
- Not tested in the real window: S16 (prompt-first Customize, draft reconciliation) is not built. The web client only checks `revision` in `isSavedProfile` and does not send `expectedRevision` yet.
