# S05 evidence: identity-safe stop and explicit force

Recorded 2026-10-28 on macOS 26.6.2 (25G83), Apple M4 Pro, arm64, Rust 1.99.1, Bun 1.4.2. The tree is uncommitted, on top of `3f0063c`; the commit that adds this file is its fingerprint. Every command below was run after the last source change.

## Decisions

- **Check order, chosen to keep the check→signal window to in-memory work.** Instance → force offer → (test scope only: the snapshot parent's start time) → one `tcp_listen_sockets()` (the target's live ports and the identities already on the confirmed port numbers) → fresh `vitals(pid)` → `revalidate` (PID ≤ 1 and Kossé itself before it considers the fresh read; then exited/unreadable, owner, request start time, start time) → test scope → `confirm` (identity in the latest snapshot, confirmed ports = live ports, so a port opened after the last scan is caught) → `kill`. The enumeration (about 3 ms) runs before the fresh read, so the vitals→kill window is unchanged. A refusal of PID 1 or a root process is therefore `refused`, not `stale`, even though such processes are not in the snapshot.
- **Owner before start time.** Without administrator rights macOS discloses neither owner nor start time of other users' processes (`vitals` on launchd and root daemons returned all `None`). The result is `refused ownerUnknown`; `otherUser` is for a visible foreign owner, including a setuid process whose effective UID differs. Both real and effective UID must equal Kossé's effective UID.
- **rustix for the signal.** sysinfo's `kill_with` returns `Option<bool>` and cannot tell `EPERM` from `ESRCH`; nix would add a crate and takes a raw `i32` PID that can be negative (a group). rustix 1.1.6 was already locked (through tempfile in tests, and `listeners` on Linux), as were its dependencies `bitflags`, `errno` and `libc`; the shipped graph gains rustix itself, with `process` and `std` only. `Pid::from_raw` debug-asserts non-negative input, so `send` converts with `i32::try_from` and rejects ≤ 1 first ([rustix `kill_process`](https://docs.rs/rustix/1.1.6/rustix/process/fn.kill_process.html)).
- **Respawn vs. released port vs. shared port numbers.** Just before the signal, the other processes on the confirmed port numbers (another address, or a socket shared across `fork`) are recorded. After the process is gone, the ports are enumerated every 100 ms for the respawn grace. Owners recorded before are `shared`, never successors. A new owner whose parent PID equals the target's parent (PID > 1) is `respawned`; any other new owner (including a launchd child, or one of several being unrelated) is `endpointTaken`; no new owner after the grace is `exited` with `shared` listing the pre-existing ones. A socket owner the OS discloses nothing about stays in the list with an unknown start time. Parent identity only explains; the parent is never signalled. A respawn slower than the grace is reported `exited`, and the next snapshot shows the new process.
- **Observation failures never read as success.** sysinfo 0.39.6 drops processes whose name it cannot read, including zombies, so "no entry" is not "gone": `vitals` reports `exited` only for zombie/dead status, `kill(pid, 0)` = `ESRCH`, or `/bin/ps -o stat=` showing `Z` (run only in that branch); otherwise `unknown`. Before the signal `unknown` is `refused unreadable`; while polling it ends in `observationFailed {processExited: false}`; a failed socket enumeration after exit in `observationFailed {processExited: true}`. A PID found with another start time counts as exited (it was reused). A failed `kill` call (or the enumeration before it) is `signalFailed` (500, nothing sent, no refresh); a crashed action task is `internal` (500, whether a signal went out is unknown, so a refresh runs).
- **Force is server-side state, not a flag.** A `stillRunning` result stores an offer for that identity and port set for 60 s, but only if the last read had the same start time and the same parent PID as at revalidation (otherwise `forceUntilMs: null`, no offer), so a PID reused within the one-second start-time resolution does not inherit it. `/api/force` without a matching, unexpired offer is `409 forceNotOffered` before any process is read; the offer is removed before `SIGKILL` is sent, and force repeats every pre-signal check.
- **Abuse bounds.** At most one stop/force per second that passes the guard and JSON checks, whatever its result (`429` + `Retry-After: 1`, same `RateLimit` as refresh); one action in flight (`429` while another is observed, at most about 6 s). Same guard as every unsafe route (Origin, JSON, 16 KiB, token).
- **HTTP status by class, one body type.** `200` for `exited`, `stillRunning`, `respawned`, `endpointTaken` and `observationFailed` (a signal was sent); `409` for `stale` and `forceNotOffered`; `403` for `refused` and `permissionDenied`; `500` for `signalFailed` and `internal`. The body is always the `ActionResult`, so S07's client parses one union.
- **No `revision` in the request.** The identity plus the exact port set, checked against the latest snapshot, is the stronger condition; a revision would only add "not from the future". `instance` is required (a confirmation from an earlier Kossé process is stale).
- **No `unsupported` variant.** v1 runs only on macOS; there is no request this build cannot attempt. Add it with a second platform.
- **Test scope.** Debug builds accept `--act-only=<PIDs>` (PID 0 and 1 refused by the parser, exit 2). Start times are read at startup; stop/force may then signal only a process matching PID + start time, or a direct child whose parent matches PID + start time (the parent's start is read before the target's fresh read), otherwise `refused outsideTestScope`. `support::Server` passes `--act-only=` (none) unless a test names its fixtures. The release binary has no such flag; `bun run dev` is unscoped by design (a real-user path, noted in CONTRIBUTING).
- **CLI stop deferred.** The blueprint requires the browser and tray paths; a `kosse stop` would need the same interactive confirmation of every port and is not part of this slice.
- **Blueprint.** `architecture.md#actions` gains the S05 outcome and the remaining races (below). No contract changed.

## Remaining race (also in blueprint/architecture.md#actions)

macOS has no pidfd: `kill(2)` takes a PID, so the process can exit and its PID be reused between the fresh read and the signal. The window is the end of one `vitals` read plus in-memory checks. XNU allocates PIDs sequentially and wraps at 99,999, so a reuse inside that window needs the PID space to cycle in microseconds. Start times have one-second resolution; they detect reuse across seconds only. The owner check bounds any mistake to the user's own processes. After the signal, a target whose PID is reused within the same second by an own-user process would look still running; the force offer therefore also requires the parent PID from revalidation, and force repeats the whole pre-signal check.

## Measurements

- **`vitals` (the read immediately before the signal):** release build, 2000 × `inspect::vitals(std::process::id())` each timed with `Instant` in a scratch binary depending on `kosse-core` (removed): p50 24 µs, p99 31–33 µs, max 132–249 µs (two runs). The fix for unreadable processes only adds work when sysinfo returns no entry.
- **Socket enumeration** (once before the signal, and each post-exit poll): 2.9 ms for the 23 TCP listeners visible on this machine.
- **End-to-end through the release binary** (curl, owned fixture with two ports and `--ignore-term`, rerun after the review fixes): `force` without offer 0.5 ms → `409 forceNotOffered`; `stop` 5.11 s → `stillRunning` (the 5 s TERM window); `force` 1.05 s → `exited` with `shared: []` (kill, then the 1 s respawn grace); the fixture is gone. A fixture that exits on TERM: `exited` in about 1.1 s; `respawned` and `endpointTaken` decide as soon as the new owner appears.
- **Idle overhead**: none added; actions run only on request and no thread or timer exists between them.
- **Binary size** (`ls -l target/release/kosse`, same `web/dist`): `3f0063c` exported with `git archive` and built the same way 3,448,320 B; this tree 3,548,096 B (+99,776 B, +2.9 %).

- **TERM exits:** a two-port fixture → `exited` with both ports and `shared: []`; the fixture's exit status is signal 15; `lsof` shows no listener; the next snapshot no longer lists it.
- **Stale and incomplete confirmations** (each followed by: same start time, same ports in `lsof`): one of two ports, an extra port → `409 portsChanged`; start time − 1 → `409 identityChanged`; no start time → `403 noStartTime`; another instance → `409 instanceChanged`; after the test stops the fixture → `409 exited`.
- **TERM ignored:** force first → `409 forceNotOffered`, untouched; stop → `stillRunning`, still untouched a second later; force → `exited`, exit signal 9; force again → `409 forceNotOffered` (single use).
- **Supervisor respawn:** stopping the supervised child → `respawned` with the supervisor as `parentPid` and a new owner PID on the same port; the child is gone; the supervisor's start time is unchanged.
- **Port taken by an unrelated process:** a supervisor waiting for the fixture's port binds it after the stop → `endpointTaken` (`shared: []`), owner's parent is that supervisor, the fixture's exit signal is 15. The successor's spawn thread is joined by a drop guard and its supervisor has a 30 s lifetime, so a failing assertion cannot leave it running.
- **Port number already shared:** a fixture on `127.0.0.1:P` and an unrelated one on `[::1]:P`; stopping the first → `exited` with the second in `shared` (not `endpointTaken`); the second is untouched.
- **`--act-only` parser:** `--act-only=0`, `=1`, `=1,2` exit 2 ("can never be signalled").
- **Refused without a signal** (test `kosse_itself_system_foreign_and_out_of_scope_processes_are_refused_without_a_signal`), on a server whose `--act-only` is empty, for both stop and force (force answers `forceNotOffered` first): Kossé's own identity → `kosseItself`; PID 1 → `systemProcess`; a root process found with `ps` → `ownerUnknown` (macOS discloses no owner of root's processes to a user); an owned fixture outside the scope → `outsideTestScope`. Afterwards Kossé still serves, `ps` reports the root process's start time unchanged, and the fixture is untouched. The test never signals anything itself.
- **Guard and limits:** wrong token → `403 tokenRequired`; wrong body → `400 invalidPayload`; `GET` → `405`; a second action within a second → `429 rateLimited` with `Retry-After: 1`.

Unit tests (`crates/core/src/action.rs`): eligibility (own user, start mismatch, exited, unreadable, other user, setuid, unknown owner, all-unknown as macOS reports foreign processes, missing start), PID 0/1/self refused before looking, confirmation against live ports (including a port opened after the scan), after-exit classification (free, shared, respawned with a shared neighbour, taken, unreadable owner kept, enumeration failure → `observationFailed`), force offered only to the same start and parent, launchd parent never explains a respawn. `crates/core/src/inspect.rs`: own process is running with a start time, launchd is never `exited`, a free PID is `exited`. `crates/core/tests/vitals.rs`: a killed, unreaped fixture (a zombie sysinfo drops) reads `exited`.

## Not verified / deferred

- **Observation failure and `unknown` through the real path.** A live own process that sysinfo cannot name, a failing socket enumeration and an unreadable start time cannot be produced on demand; the mappings are covered by unit tests and code reading of `actions::observe`. `signalFailed` and `internal` are likewise not induced.
- **`permissionDenied` through the real path.** Reaching `kill` with `EPERM` requires an own-user process the kernel still refuses (for example a hardened or restricted process); not induced. Foreign processes are refused by policy before `kill`.
- **`otherUser` through the real path.** Needs another user's process whose owner macOS discloses, which an unprivileged run does not see; covered by unit tests.
- **The check→signal race** is reduced and documented, not eliminated (no pidfd on macOS).
- **Dashboard and tray confirmation UI** arrive with S07 and S08; this slice provides the API and policy they must use. CLI `stop` is deferred (see Decisions).
- **One action at a time** means a second stop waits (429) while a TERM-ignoring process is observed for up to 5 s; revisit if S07 shows it hurts.
