## Decisions

- **Request policy on every route** (`guard::enforce` wraps the whole router):
  - Exactly one `Host`, matched case-insensitively against `127.0.0.1:<port>` or `localhost:<port>`. An absolute-form target must name the same authority. Anything else is refused with 421.
  - An API request a browser marks cross-origin is refused with 403. That means a non-matching `Origin`, or `Sec-Fetch-Site` other than `same-origin`/`none`, and it applies to GETs too. A top-level navigation to `/` from another site still works.
  - Unsafe methods need:
    - `Origin` exactly `http://<Host>`, and not `Sec-Fetch-Site: none`;
    - `application/json`;
    - a body of at most 16 KiB (413 whether declared or chunked);
    - `X-Kosse-Token`, compared in constant time.
  - No CORS headers are ever sent.
  - The token is 32 bytes from `/dev/urandom`, held in memory and new on every start. It is never read from a URL, logged or persisted.
- **Dev authority.** `127.0.0.1:47833` is admitted only with `serve --dev`, which exists only under `cfg(debug_assertions)`. The release binary rejects it with exit 2. A unit test ties the constant to `web/dev-ports.ts`.
- **Headers on every response:**
  - CSP: `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'`. Because TanStack Redact does not neutralise `javascript:` hrefs, this CSP is a real backstop.
  - `nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`, and CORP/COOP `same-origin`.
  - `Cache-Control: no-store` on the API.
- **Probe candidates (product decision).** Only processes owned by Kossé's effective user _and_ attributed to a project are probed automatically (S06 profiles may later declare HTTP).
  - Everything else is `skipped`, with reason `notOnLoopback`, `otherUser`, `knownNonHttpPort`, `knownNonHttpProcess` or `notAttributed`.
  - `POST /api/probe {identity, port}` is the explicit "try HTTP". It uses the same guard and token, and is limited to 1 per second.
    - It returns `409 staleIdentity` unless the identity and port are in the current snapshot.
    - It returns `422 notProbeable` for `otherUser`/`notOnLoopback`, which are never probed.
    - Its result is `requested: true`, both in the response and in later snapshots.
- **Probing:**
  - Connects only to loopback addresses, never a resolved name. A wildcard bind is reached through `127.0.0.1`, an IPv6-only listener through `[::1]`.
  - A server that speaks within 150 ms is `notHttp` and receives no bytes.
  - One `GET /` per probe, with `Host: localhost:<port>` and no credentials or cookies, over hyper's HTTP/1 client connection.
  - Bounds: connect 500 ms, head 2 s, body 1 s and at most 64 KiB.
  - `Location` is recorded after `redact::text` and capped at 2 KiB; redirects are never followed.
  - TLS is retried only when the plain answer looked like TLS: a `0x15`/`0x16` first byte, a silent close, or a 400 mentioning HTTPS.
  - At most 4 probes run at once; results are cached for 15 s per identity and port.
  - The only emitted URLs come from `prober::open_url`, always `http(s)://localhost:<port>/`, and that is unit-tested. Title and `Location` are untrusted text, never links.
- **TLS (product decision): rustls 0.23.46 on the ring provider, through tokio-rustls, on the same hyper connection.**
  - Roots come from `rustls-native-certs` 0.8.5, which reads the keychains' trusted certificates and trust settings locally, so mkcert-style development CAs work. It runs once, on the first TLS probe.
  - Verification is webpki in process: TLS 1.2 and 1.3, no deprecated system API.
  - **No network access during verification.** This holds by construction, not by observation: rustls/webpki contains no fetching code. Revocation is checked only against CRLs passed in, and none are, and missing intermediates are never fetched.
  - `tlsFailed` carries `failure`: `certificate` (`InvalidCertificate`, `NoCertificatesPresented`) or `handshake` (everything else). Its `reason` is untrusted text.
- **HTTP client: hyper, not reqwest.**
  - hyper is already in the graph through axum; its `client` feature added only `want` and `try-lock`.
  - reqwest brings pooling, redirect following, proxy support (it honours `HTTP_PROXY`), DNS and `url`/`idna`. Each of those is something the probe must not do.
- **SSE.**
  - A `watch` receiver: the current snapshot first, then the newest per publication. Slow clients skip revisions, and nothing is replayed on reconnect.
  - A keep-alive every 15 s.
  - Shutdown ends the streams, so graceful shutdown finishes without the 3 s drop.
  - **For S07:** browsers allow 6 HTTP/1.1 connections per origin, so one `EventSource` per tab is the budget. A dashboard opened in several tabs, or the window plus tabs, uses one stream each. No server cap was added, because event streams are cheap here (a watch receiver and a shared JSON buffer).
- **Refresh.** At most one API-triggered scan per second, with a 429 and `Retry-After: 1` beyond that. The body must be exactly the empty object `{}`; `[]` is refused.
- **Schema stays 2.** The new fields are additive, and version 2 is unreleased.
- **Rejected: `regex`.** Redaction is a small hand-written scanner instead:
  - keys split into words (and suffixes, `pass` included);
  - `key=value` and `key: value` pairs, quoted (JSON) or bare;
  - all URL user information;
  - `-u`/`--user` passwords;
  - `Bearer`/`Basic`;
  - credential prefixes, the JWT shape and PEM keys.
  - Overlapping hidden ranges merge into one `[redacted]`.

  - Warm: median 2.71 ms (min 2.61, max 2.98).
  - Phases: enumeration median 2.20 ms; inspection, attribution and metrics 0.49 ms.

- **Idle overhead.**
  - **Script.** S03's idle-sampling script, unchanged: 30 banner fixtures in 10 worktrees, a 5 s settle, then 60 s of `ps -o time=` cputime of the `serve` process, plus `/usr/bin/time -l` for it and its reaped children (git) over the whole 65.6 s.
  - **Build.** `--probe-only` needs debug assertions, so the S04 runs use a release-profile build with `CARGO_PROFILE_RELEASE_DEBUG_ASSERTIONS=true` (optimized, same code). That way only the 30 fixtures are probed, never this machine's real services.
  - **Baseline.** The S03 binary was measured in the same session with the same harness:

  | Binary (same session, same fixtures)     | Own CPU, 60 s | Incl. children, 65.6 s (user + sys) | Max RSS  |
  | ---------------------------------------- | ------------- | ----------------------------------- | -------- |
  | S03 `0f4177a`                            | 0.21 s        | 0.89 s                              | 9.7 MiB  |

## Unverified or deferred

- **No successful TLS probe.** A `response` with `tls: true` was not produced, because it needs a keychain-trusted certificate and adding a trust anchor is a global change. Only the self-signed (`certificate`) failure is tested. A `handshake` failure, such as a protocol mismatch, has no fixture.
- **Not observed:**
  - That verification makes no network access. It holds by construction (see Decisions).
  - What `rustls-native-certs` does on a machine whose keychain trust settings are unreadable. In that case every TLS endpoint would show `tlsFailed: certificate`.
- **The "400 asking for HTTPS" path** has no fixture.
- **`422 notProbeable` through HTTP.** The guard is unit-tested via `requested_target`, but no test produces another user's listener or a non-loopback-only one: binding a LAN address could raise a firewall prompt.
- **Browser behaviour is S07.** That covers real browsers' CSP, `Sec-Fetch-Site` and EventSource handling, SSE through Vite in a browser, whether Redact needs inline style attributes under `style-src 'self'`, and the 6-connections-per-origin budget.
- **No header-read timeout** (axum 0.8, as in S01). Only a local process can hold half-open connections, and only until shutdown (3 s).
- **Redaction is heuristic.** A bare positional secret, such as `mysql -pSECRET` or a lone random token, is not detected.
- **`kosse list --json` attaching to a running instance** is S08.
- **Remote CI** has not run this tree.

## Review fixes (this round)

1. **No real services in tests.** Tests no longer probe real services (debug-only `--probe-only`), and request counts are now exact.
2. **Candidate rule** (own user + project) and `POST /api/probe` for "try HTTP"; other users' processes are never probed.
3. **TLS.** rustls + ring + keychain roots, with a `certificate`/`handshake` failure split and the reason marked as untrusted text.
4. **Redaction.** JSON and colon pairs, a `pass` suffix, all URL user information, `-u`/`--user`, and merged overlapping ranges.
5. **Redirect fixture.** It now redirects to its own loopback `/next`.
6. **Entity scan.** `decode_entities` looks at most 11 bytes ahead.
7. **SSE serialization.** Each snapshot is serialized once per revision.
8. **ISC licence.** Per-crate exceptions instead of a global allow.
9. **Documentation.** `SECURITY.md`, the architecture notes, the evidence reproducibility (same-session idle baseline, dev commands, labelled size rows), `CONTRIBUTING.md`, `AGENTS.md` and the README.
