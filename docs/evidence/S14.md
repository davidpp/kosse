## Syntax and design

```text
kosse wait (--port <n> | <service>) [--http | --gone] [--timeout <dur>] [--here | --project <dir>] [--json] [--instance-port <port>]
```

- **Conditions.** Default: a matching process listens. `--http`: an endpoint of the one matching service gave any HTTP response. `--gone`: nothing matching listens.
- **With an instance.** It follows the instance's event stream and starts with one `POST /api/refresh`. Snapshots from scans that began before the wait are ignored, so the instance's current snapshot cannot call a just-started process gone. Found while testing: without this rule, `--gone` was met at once on a stale snapshot. The instance's own scanner is the only one.
- **Without an instance.** It scans in process every second (`SCAN_INTERVAL`) with one persistent `Scanner`. Profiles and probe results are applied as the scheduler applies them.
- **Requested probes (`--http`).** These are the dashboard's "try HTTP": the instance's `POST /api/probe`, or in process `Probes::request` after the same `probe::requested_target` check. Only the named endpoint is probed, first at once, then after 1 s, doubling up to 5 s. A rate-limited (`429`) or stale (`409`) request is retried after 1 s without backing off.
- **Fail fast.** An endpoint that may never be probed exits 3 (`notProbeable`). An answer that is not HTTP (banner, failed TLS, invalid probe path) exits 1 (`noHttp`). Several matching services exit 1 (`ambiguous`).
- **Output.** The service table's rows for the matching services, or `WaitAnswer` with `--json`. This is printed when the condition is met, on timeout and on the fail-fast answers. In plain mode, one `kosse: waiting up to … for …` line goes to stderr once the first observation does not meet the condition.

## Tests and the rule each guards

| Test                                                                       | Rule                                                                                                                                                                                                                                                                                                                              |
| -------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `wait::wait_returns_once_a_late_fixture_listens`                           | In process and through the instance: a wait that has reported "waiting" ends with exit 0 after a fixture binds the port, and prints that fixture's row (`PID.START` from the fixture's record).                                                                                                                                   |
| `wait::wait_gone_returns_once_the_fixture_exits`                           | Both paths: `--gone` ends with exit 0 once the owned fixture is stopped by identity, and prints no row. Through the instance this guards the freshness rule above.                                                                                                                                                                |
| `wait::wait_http_requests_probes_of_only_its_target`                       | Both paths: `--http` ends with a `requested` probe's response and `url` equal to what the probe recorded. Requests carrying the observer's instance ID reach the target at least once and at most once a second; a second HTTP fixture gets none. Through the instance, the record's `instance` is the server's (no own scanner). |
| `wait::wait_http_on_a_tcp_only_fixture_ends_with_its_probe_state`          | A banner fixture ends a 60 s `--http` wait at once with exit 1, `:<port> not HTTP` on stderr and in the `HTTP` cell, and `noHttp` and `met: false` under `--json`.                                                                                                                                                                |
| `wait::wait_times_out_with_the_last_observation_and_rejects_bad_arguments` | A timeout exits 1 (`timedOut`) after at least the timeout, with the last observation (`met: false`). No target, both targets, `--http --gone` and a malformed duration are usage errors (2).                                                                                                                                      |

Not covered by an integration test: `notProbeable`. It needs another user's process or a listener bound to a non-loopback interface only, which would trip the application firewall prompt. The rule itself is `probe::requested_target`, already used by `POST /api/probe` and its tests.

## Deviations and limits

- **Not-HTTP answers fail fast.** The blueprint names only "can never be probed" as a fast exit. A definite not-HTTP answer also ends the wait (exit 1), because retrying cannot change it. A server that answers TLS only after a restart is a new observation anyway.
- **`--gone` means "nothing matching listens".** It does not mean "this identity exited": a service restarted under a new identity still listens. Waiting on an exact identity fits S17's `<pid>.<start>` syntax if needed.
- **Extra flags.** `--project <dir>` and `--json` are added beyond the blueprint line.
- **JSON mode on stderr.** With `--json`, the "waiting" progress line is suppressed so stderr holds only a `CommandError`. clap usage errors are still plain text.
- **Incompatible instance.** When the instance's snapshot schema differs, `wait` scans in process beside it, with a note, as `list` does.
- **SSE interruption.** If the instance stops mid-wait, the wait exits 4 (`scanFailed`). It does not take over scanning.
