# S01 evidence: workspace scaffold and quality gates

Recorded 2026-10-28 on macOS 26.6.2 (25G83), arm64, mise 2026.10.11. The runs were made on an uncommitted tree on top of `a41b2d4`. The tree fingerprint is the commit that adds this file: these results describe that commit's content. Every command below was run after the last source change. Only this file and orchestrator-owned docs changed afterwards.

## Platform prerequisites

- **Target.** macOS on Apple silicon (arm64) is the only platform tested. Other platforms are unsupported for v1.
- **Xcode Command Line Tools.** Required for the system linker and SDK that rustc uses (`xcode-select --install`).
- **mise.** Run `mise trust && mise install` once per checkout. This installs the pinned Rust (through rustup), Bun, Node, cargo-nextest, cargo-deny and zizmor.
- **Network.** Needed for `mise install`, `bun install`, the first cargo fetch, and `bun run audit` (advisory database). After that, `check` needs no network.
- **Runtime.** The built binary needs neither Bun nor Node.

- **Tests.** vitest 5.0.5, jsdom 30.1.3, Testing Library (react 16.3.3, user-event, jest-dom). Playwright is not installed; it arrives with a real `test:e2e`.
- **Lint and format.** oxlint 1.89.0, oxfmt 0.74.0 ([oxfmt](https://oxc.rs/docs/guide/usage/formatter)), lefthook 2.2.2.
- **Rust.**
  - axum 0.8.9 (http1/json/tokio only)
  - tokio 1.54.1, clap 4.6.7, thiserror 2.0.21
  - serde 1.0.229, serde_json 1.0.154
  - rust-embed 8.13.0 (`debug-embed`, `mime-guess`)
- **Contracts.** [ts-rs 12.0.1](https://docs.rs/ts-rs/latest/ts_rs/) was chosen over specta. ts-rs has a stable 12.x line with serde-compat on by default. [specta](https://docs.rs/specta/latest/specta/) has had only release candidates beyond 1.0.5 since 2024.
  - **No `#[ts(export)]`.** Those test hooks write files during `cargo test`, so they are not used.
  - **One root list.** `contract::typescript_bindings()` lists the root types that API handlers serialize. It walks their dependencies through `TS::visit_dependencies` and declares each referenced type once, before its users.   - **Regeneration.** The file is rewritten only when `STACKSCAN_UPDATE_CONTRACTS=1` is set, which is what `bun run contracts` does.
- **Response validation (decision).** Generated types cannot detect a response from a different build, such as a stale dev backend. Each endpoint therefore keeps a small runtime guard over the fields the UI reads, next to its query (`web/src/api/health.ts`). No unchecked casts. Revisit only if S04's endpoint count makes per-endpoint guards costly.

## Design notes

- **Embedding.**
  - With `debug-embed`, tests run the same code path that ships.
  - `build.rs` reruns on any change under `web/dist`. This was verified by rebuilding after a hash change: the new hashed assets were re-embedded.
  - Debug builds tolerate a missing bundle so `clippy` works on a fresh checkout. A release build fails if `web/dist/index.html` is missing.
- **Routing.**
  - A client route without an extension returns `index.html`.
  - A missing file returns 404.
  - Unknown `/api` paths return 404.
  - Non-GET requests to assets return 405.
  - Files under `assets/` are `immutable`; `index.html` is `no-cache`.
  - `/.vite/license.md` is served on purpose. It is Vite's third-party license notice for the bundled JavaScript (`build.license: true`), so the binary carries its JS notices.
- **Occupied port.** The bind code runs connect probes against `127.0.0.1:P` and `[::1]:P` (250 ms each) before binding, for two reasons:
  - tokio binds with `SO_REUSEADDR`. On macOS that lets a `127.0.0.1:P` bind succeed next to a listener on the wildcard address; this was observed for real.
  - A listener on `[::1]:P` alone does not conflict with the bind at all, yet it owns `localhost:P` for most clients.

  Real occupants on `0.0.0.0`, `::` and `127.0.0.1` give `stackscan: 127.0.0.1:P is already in use by another process; stop it or choose another port with --port`, and an occupant only on `[::1]` gives the same message for `[::1]:P`. All exit with 1. An immediate restart while TIME_WAIT sockets remain still binds.

- **Bounded shutdown.** After SIGINT/SIGTERM, graceful shutdown gets 3 s. Connections still open then are dropped and logged (`stackscan: dropping connections still open after 3s`), and the process exits 0. axum 0.8's `serve` exposes no header-read timeout, so a half-sent request still holds its connection until shutdown. Revisit when S04 adds SSE.
- **Dev authority.** The browser talks only to Vite at `http://127.0.0.1:47833`, and Vite proxies `/api` to the backend at `127.0.0.1:47832`. Both ports are defined in `web/dev-ports.ts` and sit next to the production default of 47831, so a dev session never shadows an installed instance. The backend's Host/Origin allowlist (S04) must accept exactly this dev authority, and only in development.
- **Dev runner.** `scripts/dev.ts` works in this order:
  1. Install the signal handlers.
  2. Check that the Vite binary exists.
  3. Build the backend, taking the executable path from cargo's JSON messages (so `CARGO_TARGET_DIR` and other config are respected).
  4. Spawn the backend, then Vite, one after the other.

  A failure at any step stops the children already started. Paths come from `import.meta.dir`, so a checkout path with spaces works.

- **Runtime.** It is built explicitly in `main` rather than with `#[tokio::main]`, because the tray will need the main thread later.

## Review findings fixed

These came from independent review, before the first commit:

1. **Shutdown could hang indefinitely.** A client holding partial headers kept the process alive for more than 45 s after SIGTERM. Graceful shutdown is now bounded (3 s), with a binary test for a stalled client.
2. **`scripts/dev.ts` orphaned the backend** when the Vite spawn threw. Fixed with a preflight check, sequential guarded spawns, and handlers installed before the first spawn. Both failure paths were verified above.
3. **The occupancy probe had no effective test.** There is now an IPv6-loopback occupant test that fails without the probe. Occupant tests are bounded with kill-on-drop. `.config/nextest.toml` flags tests at 10 s and kills them at 30 s.
4. **An occupant on `[::1]` alone went undetected.** It is now probed.
5. **Smaller fixes:**
   - The update variable must equal `1`.
   - Contract types come from one root list plus a dependency walk.
   - The response-guard decision is recorded.
   - Script paths use `import.meta.dir`.
   - The unused `serde` dev-dependency is removed.
   - The hook's contracts glob includes `web/src/generated/**`, and the hook uses `bun run lint:web` like `lint`.
   - The release-age windows: 5 days for installs, 7 for Dependabot (zizmor minimum; first CI audit run flagged 5).
   - Module headers were added to `main.rs`, `cli.rs` and `server.rs`.

## Unverified or open

- **Remote CI.** `.github/workflows/ci.yml` (a `macos-26` check job plus an `ubuntu-latest` audit job) and dependabot have not run on GitHub yet; they run on the first push. Action SHAs were resolved from release tags on 2026-10-28.
- **Browser opening.** `serve` without `--no-open` calls `/usr/bin/open <url>`. It was never run, to avoid opening a browser on the maintainer's machine.
- **Header-read timeout.** There is none (see Bounded shutdown).
- **Orphaned children after SIGKILL.** If the dev runner itself is SIGKILLed, its children are orphaned. No signal handler can observe that.
- **Lefthook `prepare-commit-msg`.** The lefthook npm postinstall, which Bun trusts by default, installed a `prepare-commit-msg` hook. It does nothing under this config.
- **Formatter scope.** `blueprint/**` is excluded from oxfmt; formatting those documents is the maintainer's call.
