> These runs predate the rename from Stackscan to Kossé ([rename evidence](rename.md)). Commands, paths and quoted output use the current names so they stay runnable; the measurements themselves were taken under the former names.

Recorded 2026-10-28 on macOS 26.6.2 (25G83), Apple M4 Pro (14 cores), arm64, Rust 1.99.1, as an uncommitted tree on top of `8cf1780`. The tree fingerprint is the commit that adds this file. Every command below was run after the last source change; a review round (two independent lenses) preceded the final runs, and its fixes are listed at the end.

## Backend evaluation

**Gap found.** Review reproduced a silent omission in `listeners` 0.6.1, the basis that the blueprint requires before evaluating alternatives. macOS keeps 31 bytes of a process name (`pbi_name`), so an executable named 28 × `a` + `éééé` is reported as `aaaa…aé\xc3`. `listeners` decodes names strictly and keeps a socket only if the name decoded (`src/platform/macos/mod.rs`, `proc_name.rs`), so every socket of that process vanished: `lsof` listed it, `kosse list --json` did not, with no warning. The earlier whole-machine agreement (below) simply had no such process.

The same scratch build ran all three candidates against that fixture and against a fixture with an IPv4-mapped bind:

| Candidate                                                                       | Truncated name | `::ffff:127.0.0.1` bind | Assessment                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------------------------------------------- | -------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `listeners` 0.6.1 as published                                                  | dropped        | `127.0.0.1` ✓           | The defect above.                                                                                                                                                                                                                                                                                                                                                                                      |
| [`netstat2`](https://docs.rs/netstat2/0.11.2/netstat2/) 0.11.2 (MIT/Apache-2.0) | seen           | `::7f00:1` ✗            | Rejected. It misreports mapped binds. Its macOS path calls `assume_init()` on the `proc_pidfdinfo` buffer when the call returns 0 (it checks only `< 0`), which is undefined behaviour when a descriptor closes mid-scan, a routine race for a 3 s scanner. It `assert!`s on socket kinds (a panic on OS data). Last release 2025-08. Build needs `bindgen` + libclang with a hard-coded CLT SDK path. |
| [`libproc`](https://docs.rs/libproc/0.14.11/libproc/) 0.14.11 (MIT)             | seen           | not decoded             | Rejected. The wrapper is sound, but socket addresses and TCP state live in C unions (`SocketInfoProto`, `InSIAddr`) with no safe accessors. Using it would need `unsafe` in our crate (the workspace sets `unsafe_code = "forbid"`) and a reimplementation of the IPv4/IPv6 slot logic that `listeners` only fixed in 0.6.1. Build also needs `bindgen` + libclang.                                    |
| `listeners` 0.6.1 + vendored patch (chosen)                                     | seen (lossy)   | `127.0.0.1` ✓           | Two hunks: never gate a socket on its name (empty name instead), and decode names lossily. No new dependencies, no `unsafe` in our code, and the proven address decoding is kept.                                                                                                                                                                                                                      |

**Why vendoring.** It has the best correctness and maintenance trade-off. The patch is small and reviewable: `diff -ru` against the registry copy shows only these two files, plus the removed `.cargo-ok` and the crate's own `Cargo.lock`. Removing it is a two-line revert once upstream changes. `vendor/listeners` is excluded from the workspace, so our lints and formatters do not rewrite it, and oxfmt ignores it. An upstream report is suggested; none was filed.

**Name handling.** In `sockets.rs`, an empty name becomes `None`. `ProcessRecord.name` is now `string | null`. A missing name adds `name` to `metadataUnavailable`. A truncated name is reported lossily (U+FFFD for the cut byte).

**Machine-wide check.** After the patch, `list --json` was compared with `lsof -nP -iTCP -sTCP:LISTEN` three times (counts only). Every run agreed on 26 of 26 `(pid, address, port)` tuples across 16 services, and nothing appeared in only one of the two.

## Decisions

- **`listeners` behaviour handled in `sockets.rs`.**
  - `get_all()` returns UDP sockets and TCP sockets in every state; only TCP `Listen` is kept.
  - It skips PIDs whose descriptors this user may not list, without saying so. Unprivileged, that is every other user's process, system daemons included. `lsof` has the same limit. The scan reports the gap as the `otherUsersNotVisible` warning whenever it is not running as root.
  - IPv4-mapped binds are canonicalized to IPv4, which matches how `lsof` prints them.
  - The crate is confined to one module with no trait layer. Its [CHANGELOG](https://github.com/GyulyVGC/listeners/blob/main/CHANGELOG.md) shows three semver-breaking 0.x releases in 2026: 0.4.0 removed APIs, 0.5.0 added platforms, 0.6.0 added `Listener::state`.
- **Process metadata: `sysinfo` 0.39.6** ([docs](https://docs.rs/sysinfo/0.39.6/sysinfo/), MIT). Built with `default-features = false, features = ["system"]`. Findings from real runs:
  - **A PID listed twice in one `refresh_processes_specifics` call is dropped** from the table. Without deduplication, a process with two ports was reported as exited. `inspect` deduplicates, and a mutation check confirms that `repeated_pids_are_inspected_once_and_kept` catches its removal.
  - For another user's process (e.g. PID 1) the kernel refuses BSD info. `sysinfo` then reports start time `0` and no UID or cwd. `0` is mapped to "unknown".
  - A killed, unreaped child (`ps` state `Z`) is omitted by `sysinfo` on macOS. A `Zombie` status is also treated as exited.
  - Start time has one-second resolution (`pbi_start_tvsec`), so the identity is PID + start-second.
- **PID reuse between the two scan phases.** `listeners` gives no start time. If the PID of a seen socket is recycled before inspection, a naive scan would pair the old socket with the new process's identity. S05's revalidation would not catch that, because the identity really is the new process's. `scan.rs` therefore treats a process whose start second is later than the enumeration start second as not the owner, and reports `processExited`. A reuse within that same second remains undetected; this is documented in the module.
- **Snapshot contract.**
  - Fields: `schemaVersion` (1), `scannedAtMs`, `scanDurationMs`, `services` (one per PID, ordered by lowest port then PID) and `warnings`.
  - Warnings are a tagged union: `otherUsersNotVisible`, `processExited {pid, ports}`, `metadataUnavailable {pid, fields}`. Fields can be `name`, `startTime`, `user` or `cwd`.
  - `null` fields mean unknown. Unix-time `u64` fields are typed `number` explicitly, because ts-rs maps `u64` to `bigint`.
  - S03 adds revision, last-good and staleness, project attribution and metrics.
  - `blueprint/architecture.md`'s Endpoint line now matches: protocol, port, every canonical bind address, exposure; the observation time is the snapshot's `scannedAtMs`.
- **No command line yet.** Every displayed command must pass central redaction, and redaction is S04 scope, so `cmd` arrives with it. The executable path and cwd are included; they are not command lines.
- **Normalization.**
  - Sockets sharing a PID and port become one endpoint with every bind address, IPv4 first and deduplicated.
  - Exposure is `loopback`, `interface` or `allInterfaces`, judged from the widest bind.
  - A socket shared across `fork` stays one service per PID.
- **Failure semantics.**
  - Enumeration failure: `list` exits 1 with `kosse: could not enumerate TCP listeners: …`, never an empty success.
  - An exited, zombie or recycled PID is dropped from `services` and reported as `processExited`.
  - A live process with withheld fields stays a service, with `null`s plus `metadataUnavailable`.
- **Closed output streams.** All app diagnostics go through `report!`, which ignores write errors on stderr. Rust's `eprintln!` panicked (exit 101) on `kosse list 2>&1 | true`. A closed stdout (`BrokenPipe`) is already treated as success.
- **Terminal safety.** In the table, process names are untrusted. The table escapes control characters (Cc) and the invisible format characters that can reorder or hide text as `\u{…}`:
  - U+061C
  - U+200B–200F (zero-width and directional marks)
  - U+2028–202E (separators, bidi embeddings and overrides)
  - U+2060–2069 (word joiner, invisible operators, bidi isolates)
  - U+FEFF

  std has no general-category lookup, so other Cf characters (rare in process names) are not escaped. JSON escaping is serde's.

- **Deterministic generated contracts (fix to S01's generator).** ts-rs's derive collects dependencies in a `HashSet`, so declaration order changed between builds and freshness failed against a later build. `contract.rs` now visits dependencies sorted by name. Four forced rebuilds gave byte-identical output, and a unit test pins the order.

## Fixture harness (reusable by S03–S07)

- **`kosse-fixture`.** Usage: `--listen <addr[,addr…]> [--listen …] [--max-lifetime-secs N]`.
  - Each `--listen` is one ephemeral port shared by its addresses. On a port collision it retries, up to 32 times.
  - Once bound, it prints one JSON ready line (`{"pid":…,"listeners":["127.0.0.1:P","[::1]:P"]}`).
  - It answers connections with a non-HTTP banner.
  - It exits on stdin EOF or at the lifetime cap (default 120 s).
  - The browser suite (S07) can drive the same binary.
- **`Fixture::spawn`.**
  - Creates a temporary cwd whose name contains a space and `é`, and canonicalizes it.
  - Optionally copies the binary there under another name (`FixtureSpec::executable_name`, used for the truncation test).
  - Starts the fixture with piped stdio and waits at most 10 s for the ready line, without sleeping.
  - Records PID, OS start time, cwd, executable, endpoints and launch time in a serializable `FixtureRecord`.
- **Cleanup** (`stop`, and `Drop`).
  - An already exited fixture is reaped, and nothing is sent to it.
  - Otherwise the live start time must equal the recorded one. Then stdin is closed, with a bounded wait. If the fixture is still running, the identity is re-checked and `SIGKILL` goes through the harness's own unreaped `Child` handle, whose PID cannot be recycled until it is reaped.
  - A mismatch refuses with `IdentityMismatch` and touches nothing.
  - Nothing is ever matched by name.
- **Owner death.** When an intermediate owner process was SIGKILLed, the fixture exited 7 ms later on stdin EOF.
- **Locating the binary.** Fixture binaries are found next to the test executable (`target/<profile>/`). `cargo nextest run --workspace` builds them. With `-p` alone, fixture tests fail on a clean target ("fixture binary not found"), or run a stale fixture binary on a warm one. AGENTS.md and CONTRIBUTING.md say to use `--workspace`.

## Measurements

The release row comes from `cargo nextest run --workspace --release thirty --no-capture`; the debug row from the same command without `--release`. The test (`thirty_listener_scan_stays_well_under_one_interval`) scans 30 owned fixture processes with one listener each (56 TCP listeners visible in total) 20 times after a warm-up. It asserts that every fixture appears in every scan and that the median stays under 300 ms, which is 10 % of the 3 s cadence and a regression guard with roughly 100× headroom.

| Build   | min     | median  | max     | median enumeration (`listeners`) | median inspection (`sysinfo`) |
| ------- | ------- | ------- | ------- | -------------------------------- | ----------------------------- |
| release | 1.89 ms | 1.94 ms | 2.30 ms | 1.67 ms                          | 0.27 ms                       |
| debug   | 4.00 ms | 4.03 ms | 4.37 ms | 3.46 ms                          | 0.58 ms                       |

For comparison, `lsof` for the 30 fixture PIDs alone takes 15–17 ms. A one-shot release `kosse list --json`, process start included, finishes in under 10 ms wall time, with 7.5 MB maximum RSS and 57 M instructions retired (measured before the patch, which does not change the hot path). At a 3 s cadence, a 2 ms scan is about 0.07 % of one core. Resident idle overhead needs the scheduler loop, so it is measured in S03. The release binary grew from 1.8 MB to 2.0 MB.

## Review fixes (this round)

1. `listeners` silently dropped sockets with an undecodable process name. Fixed by evaluating the alternatives and vendoring the patch (above), with a fixture test under a truncation-prone name.
2. `eprintln!` panicked on a closed stderr. Fixed with `report!` and an integration test with both pipes closed.
3. A recycled PID could produce a mixed identity. Fixed by the start-after-enumeration guard and its test.
4. Docs said `-p` alone can leave the fixture binary "missing or stale". Reworded to "fails on a clean target, or runs a stale binary on a warm one".
5. Escaping covered only control characters. It now also covers bidi and zero-width characters.
6. The scan-cost bound tightened from 3 s to 300 ms.
7. Cargo.toml had a wrong path in a comment. Fixed.
8. Docs were inaccurate in places:
   - The base commit is corrected.
   - The measurement command is given.
   - The architecture Endpoint line matches the contract.
   - AGENTS.md covers backend ownership.
   - The crate doc and the `--json` help text are fixed.
   - The changelog is linked.
   - The non-macOS lockfile entries are explained.
   - CONTRIBUTING.md has test prerequisites and the `bun run test` scope.

## Unverified or deferred

- **Running as root.** Not run. Without root, `otherUsersNotVisible` is always present, and the tests branch on `id -u`.
- **Real metadata gaps through the CLI.** Not observable when running unprivileged. Proven in core with a real PID 1 inspection and an injected socket. A real name-unavailable case (`proc_name` returning 0 for a same-user process) was not produced; the `name` field path is covered only by code review.
- **Total enumeration failure.** The exit-1 path is not exercised: it requires `proc_listpids` to fail.
- **PID reuse within the same second as enumeration.** Not detected, because start times have one-second resolution.
- **Sockets shared across `fork`.** Not fixture-tested.
- **Firewall-on machines.** The `[::]` fixture is skipped with a printed reason when the application firewall is on.
- **Not built yet.**
  - The daemon path of `list --json` (S04/S08).
  - Command lines (S04).
  - User names.
  - Pruning of sysinfo's retained process table in a long-running scanner (S03).
  - Upstream report for the `listeners` name gating (suggested, not filed).
- **Remote CI.** Has not run this tree. It needs `lsof` and `socketfilterfw`, both present on macOS runners.
