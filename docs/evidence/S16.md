# S16 evidence: prompt-first Customize window

Recorded 2026-10-30 on macOS, Apple silicon, on the S16 tree (parent `b278e37`), after review round 1.

## What was built

| Where                                                                     | What                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `crates/core/src/contract.rs`, `crates/app/src/customize.rs`, `server.rs` | `GET /api/profile/prompt?root=<root>` → `ProfilePrompt {root, prompt}` from `profiles::prompt::customization`, the function `kosse profile prompt` prints. Same guard as every route and the same known-root rule as `POST /api/profile` (`404 unknownProject`); a refused root is `422 unsafeRoot` (new `ApiErrorCode`). axum's `query` feature parses the query.                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `crates/core/src/profiles/view.rs`, `effective.rs`, `authoring.rs`        | `ProjectMetadata.centralRevision`: `central::revision` of the stored central profile (`"none"` without one), the value to send as `expectedRevision`, in every snapshot (SSE). A dry run's `effective` carries the same current revision, never a predicted one.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `web/src/model/draft.ts`                                                  | `draftView`: an untouched draft shows the live profile; an edited (or refused) one stays on its base, and an outside change or a conflict is `changedOutside`, reloadable once the snapshot has the newer revision or the caller has waited long enough.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `web/src/components/customize-prompt.tsx`                                 | **Customize with your agent**: the prompt (TanStack Query, `promptQuery`) in a read-only text area, five rows, `wrap="off"` with horizontal scroll so core's line breaks are the only ones. Copy uses the async clipboard (otherwise the text is selected for ⌘C); its status is cleared on each click so a second copy is announced. An unsafe root shows core's reason and leaves the fields usable.                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `web/src/components/customize-dialog.tsx`                                 | The dialog wraps the existing form (`ProfileForm`, fields unchanged) under **Or edit fields**. A new base (an outside change to an untouched draft, or Reload) resets the draft in place, rows keyed by service ID, so nothing remounts and focus stays put. Saves send `expectedRevision`. An outside change under an edited draft, or a `409 revisionConflict`, shows the changed-outside bar ("Reload to see the new profile; your edits will be discarded"), turns Save off (`aria-disabled`) and pins the dialog title to the draft. After a 409, Reload waits for the snapshot that carries the change, at most 5 s (one scan plus the file check, `scheduler.rs`/`watch.rs`). "Updated: the profile was changed outside this window" appears only for a change the form followed, not after the user's own Reload. |

## Real window (`bun run app`)

Round 0: a real click on Copy wrote exactly `kosse profile prompt <root>` to the clipboard (checked with `pbpaste`, then the clipboard was restored), and the status read "Copied to the clipboard."

Round 1, default size and 560×620: the prompt box shows core's lines unwrapped, scrolling sideways. With the service Name field focused, an agent's `kosse profile set --instance-port <app port>` changed its value in place; it was the same element and still focused, and "Updated" showed. After typing into Project name, the next agent apply showed the changed-outside bar. Save was `aria-disabled` and the title stayed "Customize Storefront (agent)" while the card read "Storefront (agent 2)". Reload showed the agent's profile, with no alert, no "Updated" note and Save enabled. There was no horizontal page scroll. Screenshots were inspected locally and not committed (they show the machine's listeners).

## Unverified

- The `unsafeRoot` state in the window: covered by the API test, not rendered with a real hostile root.
- The Copy fallback (selection for ⌘C): the window's clipboard API worked, so the fallback was not exercised.
- The 5 s Reload bound after a 409 whose change the snapshot never shows: unit-tested logic only.
- Screen-reader announcement of a second copy: the status is cleared and set again; not checked with VoiceOver.
