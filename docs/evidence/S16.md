# S16 evidence: prompt-first Customize window

Recorded 2026-10-30 on macOS, Apple silicon, on the S16 tree (parent `b278e37`).

## What was built

| Where                                                                     | What                                                                                                                                                                                                                                                                                                                                                               |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `crates/core/src/contract.rs`, `crates/app/src/customize.rs`, `server.rs` | `GET /api/profile/prompt?root=<root>` → `ProfilePrompt {root, prompt}` from `profiles::prompt::customization`, the function `kosse profile prompt` prints. Same guard as every route and the same known-root rule as `POST /api/profile` (`404 unknownProject`); a refused root is `422 unsafeRoot` (new `ApiErrorCode`). axum's `query` feature parses the query. |
| `crates/core/src/profiles/view.rs`, `effective.rs`, `authoring.rs`        | `ProjectMetadata.centralRevision`: `central::revision` of the stored central profile (`"none"` without one), so the page learns it from every snapshot (SSE). A preview's `effective` carries the revision the applied profile will have.                                                                                                                          |
| `web/src/model/draft.ts`                                                  | `draftView`: an untouched draft shows the live profile; an edited (or refused) one stays on its base, and an outside change or a conflict is `changedOutside`, reloadable once the snapshot has the newer revision.                                                                                                                                                |
| `web/src/components/customize-prompt.tsx`                                 | **Customize with your agent**: the prompt (TanStack Query, `promptQuery`) in a read-only text area, Copy (async clipboard; otherwise the text is selected for ⌘C), what the agent does next. An unsafe root shows core's reason and leaves the fields usable.                                                                                                      |
| `web/src/components/customize-dialog.tsx`                                 | The dialog wraps the existing form (`ProfileForm`, fields unchanged) under **Or edit fields**, keyed by the revision it shows. Saves send `expectedRevision`; `409 revisionConflict` shows the same "changed outside this window" bar with Reload. An untouched form that followed an outside change says so.                                                      |

The real window reported none for the same dialog (`securitypolicyviolation` listener via `bun run app -- eval`).

`list_here_lists_only_the_callers_worktree` runs `kosse list --here` without `--instance-port`, so it asks whatever runs on the default port 47831. On this machine that is the installed 0.2.1, whose snapshot lacks `centralRevision`; the new CLI then reports "uses another snapshot version; scanning once instead" on stderr and the test's one-line assertion fails. It passes with no instance on 47831. The test reaching a real instance is a pre-existing isolation gap.

## Real window (`bun run app`)

`start`, seed a central profile with `kosse profile set … --instance-port <app port>`, search `storefront`, click Customize: the dialog opens on the prompt with Copy focused and no CSP violation. A real click on Copy: the status reads "Copied to the clipboard." and `pbpaste` equals `kosse profile prompt <root>` byte for byte (the clipboard was restored afterwards). `kosse profile set` while the dialog was open: the untouched form showed the new name and "Updated: the profile was changed outside this window."; after typing into Project name, the next agent apply showed the alert with the edit kept, Save left the dialog open and the configuration without the edit, and Reload showed the agent's profile. At 560×620 the page has no horizontal scroll. Screenshots were inspected locally and not committed (they show the machine's listeners).
