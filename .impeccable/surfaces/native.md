# Native dashboard — Operate

## Direction

A brief operational view beside editors and terminals: identify a local service and act on the exact process. This is the owner-approved native Rune replacement of the browser dashboard, built from the existing operational contract. There was no seeded concept roll or approved comp; this document records the implemented direction, not retrospective workshop evidence.

## First viewport

The Kibernetyk Mono name shares the title row with connection status and Refresh. Search and Projects only / All listeners follow. Project/worktree groups occupy the main viewport: name, branch, service count, customization access, then rows with process label, package, ports, HTTP observation, compact CPU/memory/age and Inspect/Stop. Observation notes are disclosed from the footer so they do not displace the primary task by default.

## Signature interaction

Filter by a project, process or port, then inspect the chosen PID plus start identity. The inspector preserves the runtime facts beneath any local display name; live revisions do not turn the selection into a different process. On wide windows it sits beside the filtered list; on narrow windows it takes the content pane. Done returns to the retained filter.

## Customization

A project/service sidebar anchors a structured editor. Name inheritance, local matching rules, protocol hints, links and entry availability remain explicit. Details scroll independently above a fixed Save changes / Cancel footer. Individual-entry removal changes the draft; whole-project removal is separately confirmed. Repository values remain inherited and read-only, and running processes are unaffected. Detail and navigation are inert while saving.

## Form and authority

Neutral light/dark Rune layers, compact Inter text and system mono facts, with Québec blue selected controls. Relay's separated K and optically tuned menu-bar geometry remain brand assets. The current code and DESIGN.md supersede review screenshots captured before the density and blue-control corrections. Behavioral and visual acceptance belongs in docs/evidence; this surface brief makes no test-pass claim.
